# DeepLabCut intent integration

DeepLabCut coordinates now feed a trainable motion classifier and an optional
RGB-plus-motion classifier. This is a new runnable path in `pose_intent`, not a
skeleton overlay or a replacement for the old checkpoint. The existing desktop
monitor still runs its RGB model. Use `Pose Intent.cmd` for the new workflow.

No trained screwdriver pose model or improved intent weights are included.
Synthetic verification establishes code execution, not intent accuracy or live
throughput with a real pose model. Record and annotate pilot footage first.

## Architecture

`video -> DLC landmarks -> causal movement features -> GRU -> intent`

Fusion additionally uses frozen ResNet101-LSTM features from the existing RGB
checkpoint. Training caches its 128-dimensional embeddings, so only the small
GRU and combination layers are trained. No ImageNet download occurs. The RGB
checkpoint is supplied separately for live/replay and checked by SHA-256.

Shared features include shoulder-normalized landmark positions and velocities,
wrist-to-tool distance/change, elbow angles, torso motion, screwdriver direction,
and optional wrist-to-workspace-center distance. Masks explicitly identify
missing/low-confidence observations. Likelihood values are tracker scores, not
calibrated intent confidence. Distances are 2D, not proof of physical contact.

## Environment

This laptop already has `deeplabcut-gpu`. The launcher activates it. For another
Windows NVIDIA machine, using an Anaconda/Miniconda prompt:

```powershell
conda create -n deeplabcut-gpu python=3.12 pip -y
conda activate deeplabcut-gpu
python -m pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r requirements-pose.txt
python -m pip check
python -m pose_intent --help
```

The adapter targets DeepLabCut **3.0.1**, standard **single-subject bottom-up**
PyTorch models (`method: bu`). Multi-person, top-down models and cropped DLC
projects are rejected. Keep exactly these bodypart names in the project:

```text
left_shoulder
right_shoulder
left_elbow
right_elbow
left_wrist
right_wrist
screwdriver_tip
screwdriver_handle
```

Train/evaluate the pose model in DeepLabCut first. Include pose-labeling frames
only from development sessions, not final test sessions. The code cannot verify
which footage was used to train an externally supplied DLC snapshot.

## 1. Export poses from each original recording

Open a terminal in this repository. Replace the example paths:

```powershell
& ".\Pose Intent.cmd" extract --video "Camera Recordings\take.avi" --project "DLC Projects\project\config.yaml" --model-config "DLC Projects\project\dlc-models-pytorch\MODEL\train\pytorch_config.yaml" --snapshot "DLC Projects\project\dlc-models-pytorch\MODEL\train\snapshot-100.pt" --output "Pose Data\take.csv"
```

The extractor saves a standard DLC-style CSV and a `.pose.json` provenance
sidecar, one row per original decoded frame. It analyzes full frames, without
future-frame smoothing. Use the same project/config/snapshot for every take.
Changing any of those files requires re-extraction; their hashes are checked at
live startup. Ordinary DLC exports can be read by the table loader, but the full
workflow requires the provenance sidecar generated by this command.

## 2. Review intent segments and splits

Copy `examples/pose_manifest.json` to a local file under `Pose Data`. Update all
paths relative to the manifest location, copy recording IDs from the matching
recording JSON, and add every take. Review segment start/end times in **capture
seconds** using `frame_timestamps_seconds`; AVI playback time may differ.

Set `annotations_confirmed: true` only after review. The recorder's planned
scenario is not accepted as ground truth. Use `INTERACTION`, `PASSTHRU`, `WAIT`.
Segments are [start, end), ordered and nonoverlapping; unlabeled gaps are skipped.
Choose a consistent observable definition for when INTERACTION begins. If the
goal is anticipation, label the approach phase intentionally; footage of an
already-grasped tool alone cannot teach early intent.

Every take needs `train`, `val`, or `test`. Each development split must contain
all three classes. Whole sessions remain in one split. Participants are also
grouped by default; set `group_participants: false` only for a same-person,
new-session experiment, and describe that limitation in results. Duplicate
take IDs, video paths, copied video contents and cross-split groups are rejected.

## 3. Prepare synchronized windows

```powershell
& ".\Pose Intent.cmd" prepare --manifest "Pose Data\manifest.json" --input-config examples\pose_input.json --rgb-weights "D:\models\legacy-intent.pth" --output "Pose Data\windows"
```

Omit `--rgb-weights` for motion-only data. Supplying it enables all three-way
comparisons on identical windows. Output directories must be empty.

The new default is **16 samples at 10 Hz**, spanning 1.5 seconds first-to-last.
It is a starting experiment, not a claim that this interval is optimal. This is
deliberately separate from the old monitor's 16 consecutive frames. The shared
sampler selects distinct observations at or before target times. Timing gaps
and poor tracking are rejected and counted. No frame padding, future interpolation
or symmetric smoothing is used. Windows are labeled by their endpoint; their
preceding context can cross an action onset.

The input JSON records sample rate, count, confidence cutoff, minimum tracking
coverage and freshness limit. Optionally set `workspace_center` to normalized
image coordinates `[x, y]` for one fixed camera setup. Leave it null for mixed
camera setups; a single workspace coordinate cannot represent different angles.
If live pose throughput cannot sustain the selected rate, prepare/retrain at a
lower rate instead of silently changing checkpoint settings.

The legacy RGB checkpoint's training frame rate is unknown. Its frozen features
are a starting point to validate, not proof of compatibility with the new timescale.

## 4. Train and compare

```powershell
& ".\Pose Intent.cmd" train --data "Pose Data\windows" --modality motion --output "Pose Runs\motion"
& ".\Pose Intent.cmd" train --data "Pose Data\windows" --modality fusion --output "Pose Runs\fusion"
& ".\Pose Intent.cmd" evaluate --data "Pose Data\windows" --checkpoint "Pose Runs\motion\best.pt" --split val --output "Pose Runs\motion-val.json"
& ".\Pose Intent.cmd" evaluate --data "Pose Data\windows" --checkpoint "Pose Runs\fusion\best.pt" --split val --output "Pose Runs\fusion-val.json"
```

Feature normalization uses observed TRAIN values only. Best checkpoint selection
uses validation macro F1. Final test evaluation is a separate explicit command:
change `--split val` to `--split test` and use new report filenames after tuning
is finished. Test evaluation rejects sessions used during training/selection.

Reports include confusion matrices, per-class precision/recall, false interaction
and missed interaction window rates, predictions with timestamps, and first
interaction detection relative to annotated onset (one-second anticipation
interval). Negative offsets indicate early detection. Compute latency is excluded
from offline event timing. Inspect false alarms alongside early detections.
The RGB baseline uses the same windows, without the old GUI's vote smoothing.
Tracking-rejected windows are unavailable, never counted as correct. Review
rejection counts and live availability as well as classification scores.

## 5. Replay and then run live

```powershell
& ".\Pose Intent.cmd" replay --checkpoint "Pose Runs\fusion\best.pt" --rgb-weights "D:\models\legacy-intent.pth" --video "Camera Recordings\take.avi" --metadata "Camera Recordings\take.json" --pose "Pose Data\take.csv" --output "Pose Runs\replay.jsonl"
& ".\Pose Intent.cmd" live --checkpoint "Pose Runs\fusion\best.pt" --rgb-weights "D:\models\legacy-intent.pth" --project "DLC Projects\project\config.yaml" --model-config "DLC Projects\project\dlc-models-pytorch\MODEL\train\pytorch_config.yaml" --snapshot "DLC Projects\project\dlc-models-pytorch\MODEL\train\snapshot-100.pt" --camera 0 --output "Pose Runs\live.jsonl"
```

Motion checkpoints do not need `--rgb-weights`. Press Q to close live preview.
Capture timestamps come from the monotonic clock when a camera frame is read;
they are not hardware exposure timestamps. The capture and pose workers are
separate; the queue keeps the newest waiting frame. Pose/image pairs retain
the same frame ID and timestamp. Low coverage, timing gaps, processing failures
and stale predictions display UNAVAILABLE with no class probability.

The preview is for reviewing intent predictions and does not issue robot
commands. The existing monitor continues to be the RGB baseline. This new path
must be evaluated with real held-out footage before claiming any improvement.

## Verification and local data

```powershell
python -m pytest tests/test_pose_intent.py -q
```

Tests cover time alignment, missing landmarks, causal features, source/split
contracts, motion/fusion gradients, CPU training and replay parity, and CUDA
optimizer steps when available. They use generated fixtures, not real recordings.

Keep raw footage in `Camera Recordings`, DLC projects in `DLC Projects`, prepared
data in `Pose Data`, and runs in `Pose Runs`. These directories are Git-ignored.
No raw videos are published. Deliberately shared `.pt`/`.pth` weights use Git LFS.

Official installation: https://deeplabcut.github.io/DeepLabCut/docs/installation.html
